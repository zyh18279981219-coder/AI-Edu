## 调整范围

本次调整只作用于本地克隆库 `127.0.0.1:3307/ai_education_design`，远程库未执行结构修改。

本地库来源为远程 `ai_education` 的 `mysqldump` 克隆，后续数据库设计、ER 图和表结构说明均以本地克隆库为准。

## 已修正问题

1. 删除业务 SQLite 路线，后端统一走 MySQL。
2. 建立本地 MySQL 设计实例和专用用户，避免直接改远程库。
3. 补充作业任务、提交、批改事件之间的外键关系。
4. 新增职业岗位、职业能力、课程能力映射三张表，支撑课程数字孪生中的“岗位能力-知识点”映射。
5. 新增教学公告、讨论主题、讨论回复、教研记录表，支撑教师数字孪生证据来源。
6. 修正 `quiz_attempts` 中知识点名称误写入 `node_id` 的记录，无法自动匹配的记录已备份。
7. 将 `diagnosis_reports` 中旧 `course_demo` 课程记录统一归并到主课程 `course_big_data`，原记录已备份。
8. 为 `twin_profile_nodes` 补充 `course_id`，并建立 `username + course_id + node_id` 唯一约束。
9. 修正学生画像节点中可自动匹配的知识点，无法匹配的旧测试节点已备份后从主表移除。
10. 重建 `user_interaction` 为事件日志表，替换原先无自增主键、课程字段类型不合理的旧结构。
11. 为用户活动日志、教师学生关系、LLM 日志、资源、测验、诊断等表补充外键和索引。

## 仍需确认的问题

1. `username` 与 `user_id` 仍然双轨存在。当前策略是保留 `username` 作为展示和兼容字段，新增或补齐 `user_id` 作为可约束字段；是否进一步统一到全系统只以 `user_id` 为主，需要结合前后端接口改造成本确认。
2. `payload_json` 仍保留在多个表中。当前策略是核心查询字段实体化，AI 上下文、原始证据、扩展内容继续放在 JSON 字段；最终表结构说明中需要明确哪些字段是主业务字段，哪些是扩展证据字段。
3. `course_node_relations` 当前无业务数据，只完成结构规范化。后续如果课程图谱要表达先修、相关、包含、支撑等边关系，需要在设计文档里明确关系类型枚举。
4. 教师数字孪生事件表仍以事件日志为主，暂未拆成强事务表。原因是事件来源包括作业、互动、教研、干预等多个模块，适合先作为证据流保留。
5. 备份表不属于正式业务模型，正式 ER 图应排除这些表。
