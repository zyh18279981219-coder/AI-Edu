# 当前代码数据库依赖盘点

盘点时间：2026-06-27

盘点范围：`zyh` 分支重构后的 `backend/`、`database/schema.sql`、`backend/DatabaseModule/mysql_schema_clean.sql`、本地 MySQL 克隆库 `127.0.0.1:3307/ai_education_design`。

## 1. 当前本地库状态

本地 MySQL 已启动，后端可连接并启动。当前库中已有表：

| 表名 | 来源 | 说明 |
|---|---|---|
| `users` | `database/schema.sql` | 用户主表 |
| `user_profiles` | `database/schema.sql` | 用户扩展信息 |
| `learning_plans` | `database/schema.sql` | 学习计划主表 |
| `learning_plan_nodes` | `database/schema.sql` | 学习计划节点/载荷表 |
| `user_activity_log` | 后端启动时由 `mysql_store.py` 补建 | 学习连续天数、通知模块使用 |

初次盘点时，`database/schema.sql` 与 `backend/DatabaseModule/mysql_schema_clean.sql` 完全一致，但都只包含 4 张基础表。后端启动后只额外补建 `user_activity_log`，并不会补齐课程、画像、作业、互动、5E 等业务表。

修复进展：已将 `database/schema.sql` 扩展为第一版权威 schema，并同步 `backend/DatabaseModule/mysql_schema_clean.sql`。当前本地开发库已有 34 张表，覆盖课程底座、学生画像、测验证据、作业、教学互动、教师事件、行业能力映射、5E 交互等当前代码与需求主链路所需的基础结构。

## 2. 代码实际依赖的表

### 2.1 用户、会话与日志

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|
| `users` | 有 | `backend/DatabaseModule/mysql_store.py` | 可用 |
| `user_profiles` | 有 | `backend/DatabaseModule/mysql_store.py` | 可用 |
| `teacher_student_links` | 缺失 | `mysql_store.py:list_teacher_students/replace_users` | 教师-学生关系接口会失败 |
| `sessions` | 缺失 | `mysql_store.py:save_session/get_session/list_sessions` | 登录态、当前学习上下文无法稳定落库 |
| `user_states` | 缺失 | `mysql_store.py:save_user_state/get_user_state`，行业情报任务状态、教师外部指标 | 行业情报快照和教师扩展指标无法保存 |
| `llm_logs` | 懒创建 | `mysql_store.py:_ensure_llm_logs_table` | 只有访问日志接口时才建，不在正式 schema 中 |
| `user_activity_log` | 运行期补建 | `learning_streak_service.py`、`notification_service.py` | 已存在，但应纳入正式 schema |

### 2.2 课程数字孪生与课程资源

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|
| `courses` | 缺失 | `mysql_store.py:sync_course_from_graph`，5E 课程函数 | 课程底座无法持久化 |
| `course_metadata` | 缺失 | `mysql_store.py:get_course_payload/sync_course_from_graph` | 课程图谱 JSON 无法保存/读取 |
| `course_nodes` | 缺失 | `mysql_store.py:sync_course_from_graph/list_learning_nodes_for_course`，`app.py` 学习进度统计 | 知识点、章节、小节结构无法持久化 |
| `resources` | 缺失 | `mysql_store.py:list_resources_for_node_name/soft_delete_resource`，5E 资源函数 | 本地资源、外部资源绑定无法持久化 |
| `course_node_relations` | 缺失 | `apply_local_design_adjustments.py` | 需求中弱化前置关系后，该表仅可用于覆盖关系、补充学习项来源关系等，不应再写“前置知识点” |

结论：课程数字孪生最核心的课程结构、知识点和资源表都没有进入当前正式 schema。这是第一批必须补齐的表。

### 2.3 学生数字孪生、测验与诊断

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|
| `twin_profiles` | 缺失 | `mysql_store.py:save_twin_profile/get_twin_profile/list_twin_profiles` | 学生画像主表缺失 |
| `twin_profile_nodes` | 缺失 | `mysql_store.py:_load_twin_nodes_for_usernames/save_twin_profile` | 知识点掌握状态缺失 |
| `twin_history` | 缺失 | `mysql_store.py:save_twin_history/get_twin_history` | 画像趋势无法保存 |
| `quiz_attempts` | 懒创建 | `mysql_store.py:record_quiz_attempt`，通知模块 | 测验证据不在正式 schema 中 |
| `diagnosis_reports` | 缺失 | 目前主要出现在种子脚本和调整脚本 | 诊断智能体还没有稳定诊断结果表 |

结论：学生数字孪生目前更像“代码里有服务，库里没结构”。诊断智能体在需求文档中很重要，但代码里还没有正式的诊断结果落库模型，需要作为新开发内容补上。

### 2.4 个性化学习路径

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|

### 2.5 作业与实践评测

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|
| `homework_assignments` | 缺失 | `HomeworkModule/repository.py` | `DB_AUTO_MIGRATE=0` 时不会自动建表 |

| 表名 | 当前 schema | 主要使用位置 | 问题 |
|---|---:|---|---|

## 3. 主要冲突和风险

| 等级 | 问题 | 影响 | 处理建议 |
|---|---|---|---|
| P1 | 正式 schema 严重不完整 | 后端启动成功，但课程、画像、作业、互动等业务接口会在运行时缺表 | 先补齐权威 schema |
| P1 | `mysql_schema_clean.sql` 与 fallback 建表逻辑不一致 | schema 文件存在时 fallback 不执行，导致开发者误以为有表 | 保留单一权威 schema，后端启动只做轻量幂等修复 |
| P1 | `DB_AUTO_MIGRATE=0` 与模块仓储建表逻辑冲突 | 作业、互动、教研、教师事件表不会自动创建 | 将这些表纳入 `database/schema.sql` |
| P1 | 课程核心表缺失 | 课程数字孪生主链路无法落地 | 第一批补 `courses/course_metadata/course_nodes/resources` |
| P1 | 学生画像核心表缺失 | 学生数字孪生、诊断、路径都缺数据底座 | 第一批补 `twin_profiles/twin_profile_nodes/twin_history/quiz_attempts` |
| P2 | 诊断智能体无正式结果表 | 诊断结果难以追溯，教师端证据下钻难做 | 新增诊断结果、诊断证据、诊断建议表 |
| P2 | 行业能力映射只在调整脚本里，业务未打通 | 需求里的职业能力映射无法真实使用 | 新增教师审核接口和能力映射持久化 |
| P2 | 5E 存在单数表模型 | 容易生成另一套用户/画像表 | 改 5E 模型引用到统一表 |
| P2 | 学习路径存储过于 payload 化 | 难以查询路径节点状态、补充学习项和任务关联 | 拆分路径节点与任务关联表 |
| P3 | 作业类型口径不统一 | 需求和实现表述不一致 | 明确 `objective` 可细分客观题/选择题，删除或重定义 `mixed` |

## 4. 建议修复顺序

1. 先建立权威 schema：以 `database/schema.sql` 为主，补齐当前代码必需表，并同步更新 `backend/DatabaseModule/mysql_schema_clean.sql`，避免两份 schema 分叉。
2. 第一批补基础运行表：`teacher_student_links`、`sessions`、`user_states`、`llm_logs`、`user_activity_log`。
3. 第二批补课程底座表：`courses`、`course_metadata`、`course_nodes`、`resources`、`course_node_relations`。
4. 第三批补学生画像和测验证据表：`twin_profiles`、`twin_profile_nodes`、`twin_history`、`quiz_attempts`。
5. 第四批补作业、教学互动和教师事件表：作业两表、教学互动三表、教研表、教师画像事件表。
6. 第五批补需求新增表：诊断结果/证据、职业能力映射、个性化路径节点、干预任务包、5E 有效度指标。
7. 最后修改代码：移除 SQLite 残留、统一表名、统一数据访问层、把模块运行期建表迁回 schema。

## 5. 下一步开发建议

第一版 `database/schema.sql` 已完成扩展，并在临时空库和本地开发库中导入验证通过。下一步不要直接改前端页面，建议继续做以下验证和清理：

- 能从空库导入成功。
- `python main.py` 能启动。
- 课程同步接口能创建课程、节点和资源。
- 作业模块能创建作业和提交。
- 学生画像能保存和读取。
- 5E 不再依赖单数 `user`、`twin_profile` 表。

完成后再进入课程数字孪生、学生数字孪生、诊断智能体、个性化路径和教师看板这条主链路开发。
