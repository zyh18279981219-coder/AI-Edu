# 学生端首页 V2 小幅改进总结

本次完成了学生端首页的第一阶段小幅改进，目标是在不破坏现有功能的前提下，让首页第一屏视觉更接近 `frontend-prototype/student-v2.html` 原型。

## 修改文件

### `frontend-vue/src/views/student/HomeView.vue`

- 新增用户信息获取，用于展示 `displayName`。
- 新增首页统计数据计算，包括总体掌握度、已完成知识点、待完成作业、连续学习天数。
- 将原有 `PageHero` 替换为新的欢迎横幅组件。
- 保留现有核心功能，包括知识图谱、学习定位、继续学习跳转等。

### `frontend-vue/src/styles/main.css`

- 新增 `.student-home-v2-hero` 系列样式。
- 使用独立类名前缀，避免与现有全局样式冲突。
- 增加响应式样式，支持移动端展示。

### `frontend-vue/src/layouts/StudentLayout.vue`

- 调整学生端导航顺序：首页、学习中心、诊断、作业、行业资讯、设置。
- “学习中心”指向 `/student/course-content`，对应课程内容页。
- “诊断”指向 `/student/student-twin`，对应数字孪生页。
- 保留所有现有路由，未删除任何页面。

## 验收结果

- `npm run build` 构建通过。
- 无 TypeScript 诊断错误。
- 知识图谱功能完整保留。
- 学习定位功能正常。
- 继续学习跳转正常。
- 首页视觉更接近 `student-v2` 原型。

## 说明

- “待完成作业”和“连续学习天数”目前使用安全 fallback，默认返回 `0`，因为现有 API 暂未提供这些数据。

- 样式统一使用 `student-home-v2-` 局部前缀，降低全局样式冲突风险。

### 风险等级推断规则

**推断逻辑：**

```typescript
// 基于 summary.risk_alerts 数组推断
if (alerts.some(r => r.level === 'high')) {
  return '高风险'; // 红色
}
if (alerts.some(r => r.level === 'medium')) {
  return '中等风险'; // 黄色
}
return '低风险'; // 绿色
```

**规则说明：**

1. 如果风险预警中存在任何 `high` 级别的风险，整体判定为"高风险"
2. 如果没有 `high` 但存在 `medium` 级别的风险，判定为"中等风险"
3. 如果没有任何风险或只有 `low` 级别的风险，判定为"低风险"

**颜色映射：**

- 高风险：红色（#dc2626）
- 中等风险：黄色（#f59e0b）
- 低风险：绿色（#059669）

### 作业状态筛选规则

**状态判断逻辑：**

```typescript
// 基于 assignments 和 mySubmissions 计算
function getStatusLabel(assignmentId: string): string {
  const submission = mySubmissions.find(s => s.assignment_id === assignmentId);
  if (!submission) return "待提交";
  if (submission.status === "graded") return "已评分";
  return "已提交";
}
```

**筛选规则说明：**

1. **待完成**：在 `assignments` 中但在 `mySubmissions` 中找不到对应记录的作业
2. **已提交**：在 `mySubmissions` 中有记录且 `status !== "graded"` 的作业
3. **已评分**：在 `mySubmissions` 中有记录且 `status === "graded"` 的作业

**保守规则：**

- 如果作业在 `assignments` 中但没有提交记录，判定为"待提交"
- 如果提交记录的 `status` 字段不是 `"graded"`，统一判定为"已提交"
- 只有明确标记为 `"graded"` 的提交记录才判定为"已评分"

**颜色映射：**

- 待提交：黄色（#fef3c7 背景，#92400e 文字）
- 已提交：蓝色（#dbeafe 背景，#1e40af 文字）

### 3. 逾期判断规则详解

**判断流程：**
```
1. 检查作业是否有 due_at 字段
   ├─ 无 → 不是逾期
   └─ 有 → 继续

2. 检查是否有提交记录
   ├─ 有提交记录 → 不是逾期（即使过期也不显示为逾期）
   └─ 无提交记录 → 继续

3. 比较当前时间与截止时间
   ├─ 当前时间 > 截止时间 → 已逾期
   └─ 当前时间 ≤ 截止时间 → 待提交
```

**示例场景：**

| 场景 | due_at | 当前时间 | 提交记录 | 状态 |
|------|--------|----------|----------|------|
| 场景1 | 2026-05-01 | 2026-05-06 | 无 | **已逾期** |
| 场景2 | 2026-05-01 | 2026-05-06 | 有（已提交） | 已提交 |
| 场景3 | 2026-05-01 | 2026-05-06 | 有（已评分） | 已评分 |
| 场景4 | 2026-05-10 | 2026-05-06 | 无 | 待提交 |
| 场景5 | null | 2026-05-06 | 无 | 待提交 |

**关键点：**
- 已提交或已评分的作业，即使过期，也不显示为"已逾期"
- 这样设计是为了避免混淆：学生已经完成了作业，不应该再提示逾期
- 逾期状态仅针对"未提交且已过期"的作业
