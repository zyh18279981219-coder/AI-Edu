# AI-Education 需求文档

> 版本：v1.0  
> 编写日期：2026-05-13  
> 适用范围：当前仓库 `AI-Education2` 的后端、前端、数据与智能体模块  
> 文档口径：以现有实现为基础，覆盖已落地功能、当前约束与后续可验收要求。

## 1. 项目概述

AI-Education 是一个面向教学与学习场景的智能教育平台。系统围绕“大数据课程”学习过程，提供学生学习、教师教学管理、管理员运维查看、数字孪生画像、个性化路径推荐、作业与判题、AI 干预、教学互动、教研协同、行业情报分析等能力。

系统采用三端角色模型：

- 学生端：完成课程学习、AI 问答、测验、作业、数字孪生诊断、个性化学习路径和行业情报查看。
- 教师端：查看班级学情、管理课程资源与作业、发起 AI 干预、维护教学互动与教研记录、查看教师数字孪生。
- 管理端：查看用户、教师、学生与 LLM 调用日志等平台运行数据。

## 2. 建设目标

1. 为学生提供围绕课程知识图谱的学习闭环：学习资源、问答、测验、总结、计划、路径推荐、作业反馈和画像诊断。
2. 为教师提供班级学情洞察和干预工具：班级概览、知识点热力图、学生趋势、作业发布批改、AI 干预任务包、互动与教研记录。
3. 将学习行为、测验结果、LLM 交互、作业表现沉淀为学生数字孪生画像，为个性化学习提供数据基础。
4. 将教师互动、教研、批改、干预等行为沉淀为教师数字孪生，为教学质量改进提供依据。
5. 支持课程、资源、测验和画像数据实体化存储，降低历史 JSON 数据并存阶段的数据不一致风险。
6. 支持本地开发、演示与团队协作，提供可复现的数据库种子、接口自测和前端构建流程。

## 3. 用户角色

| 角色 | 主要诉求 | 关键权限 |
| --- | --- | --- |
| 学生 | 学习课程、完成测验和作业、获得 AI 辅导与个性化建议 | 访问个人学习数据、提交测验/作业、查看个人画像与路径 |
| 教师 | 掌握班级学情、布置与批改作业、对学生进行精准干预 | 查看关联学生数据、管理作业与资源、生成/推送干预包 |
| 管理员 | 查看平台用户与运行记录，辅助排查问题 | 查看用户列表、教师/学生列表、LLM 日志 |
| 系统服务 | 数据采集、画像计算、RAG 检索、LLM 调用、OJ 判题 | 后台任务、数据库读写、外部服务调用 |

## 4. 业务范围

### 4.1 当前范围

- 统一登录、会话、角色路由与个人信息维护。
- 课程知识图谱、学习节点、学习资源、PDF 选择与资源上传/删除/恢复。
- AI 课程问答、章节总结、在线测验、测验总结和学习计划生成。
- 学生数字孪生、课程画像、趋势跟踪、弱项识别、路径推荐。
- 教师班级看板、学生详情、趋势、节点排名、热力图、教师数字孪生。
- 作业发布、编辑、发布/关闭/重开、学生提交、AI 辅助批改、教师终审、代码实践判题。
- AI 干预任务包：教师诊断、草稿生成、编辑推送、学生接收、答题、进度、教师评分。
- 教学互动：公告、讨论话题、帖子、学生提问、教师回复、互动统计。
- 教研协同：教研记录的创建、编辑、删除和上下文选项。
- 行业情报：岗位抓取、相关性过滤、LLM 技能分析、图表统计、任务状态恢复与取消。
- 管理端用户和 LLM 调用日志查看。

### 4.2 当前不重点覆盖

- 多租户学校/机构隔离。
- 完整权限后台配置。
- 生产级身份认证，如 OAuth、短信、单点登录。
- 大规模分布式任务调度。
- 完整线上支付、证书、考试防作弊等业务。

## 5. 功能需求

### 5.1 认证与会话

**FR-001 统一登录**

- 系统应支持学生、教师、管理员使用账号和密码登录。
- 登录成功后应创建 `session_id` Cookie。
- 前端应根据 `user_type` 自动跳转到对应首页。
- 未登录用户访问受保护页面时应跳转到登录页。

**FR-002 当前用户**

- 系统应提供当前登录用户查询能力。
- 返回信息应包含用户标识、角色、展示名和角色相关扩展数据。

**FR-003 退出登录**

- 用户应能主动退出。
- 退出后应清理会话并回到登录页。

**FR-004 个人资料与密码**

- 学生端应支持更新个人资料。
- 学生端应支持修改密码。
- 修改失败时应返回明确错误信息。

### 5.2 学生端学习中心

**FR-101 课程知识图谱**

- 学生应能查看当前课程知识图谱。
- 系统应优先从实体表 `courses`、`course_nodes` 读取课程结构。
- 当实体数据缺失时，可使用历史课程 JSON 做一次性兜底导入。

**FR-102 学习节点列表**

- 学生应能查看课程学习节点。
- 节点应包含层级、名称、完成状态和必要的扩展信息。

**FR-103 节点资源**

- 学生应能按知识节点查看对应学习资源。
- 资源可包含 PDF、视频、文本或外部链接等类型。

**FR-104 PDF 资源阅读**

- 学生应能选择当前学习 PDF。
- 系统应能通过后端接口读取指定 PDF 文件。

**FR-105 学习进度**

- 学生应能查看总体、章节、小节和知识点维度的学习进度。
- 学习进度应基于课程节点和用户画像节点数据计算。

**FR-106 连续学习与活动记录**

- 系统应记录学习活动。
- 学生应能查看近期连续学习天数或学习状态。

### 5.3 AI 辅导、总结与学习计划

**FR-201 AI 课程问答**

- 学生应能围绕当前课程内容向 AI 助教提问。
- 系统应结合 RAG 检索能力回答课程相关问题。
- 问答过程应支持会话上下文。
- LLM 调用应记录日志，便于管理端审计。

**FR-202 章节总结**

- 学生应能按主题生成学习总结。
- 总结结果应以可读文本返回，可用于复习。

**FR-203 在线测验**

- 学生应能按知识点开始测验。
- 系统应生成题目并维护测验状态。
- 学生提交答案后系统应给出下一步状态或结果。

**FR-204 测验完成与进度同步**

- 学生完成测验后，系统应记录测验尝试。
- 达到通过阈值后，应同步更新课程完成状态。
- 测验成绩应同步进入数字孪生画像。

**FR-205 测验总结**

- 系统应基于题目、答案、得分生成测验总结。
- 总结应包含薄弱点和复习建议。

**FR-206 学习计划**

- 学生应能输入目标、优先级、截止天数生成学习计划。
- 系统应支持从测验结果生成补救学习计划。
- 生成结果应持久化并可在学生端查看。

### 5.4 学生数字孪生与个性化路径

**FR-301 学生画像采集**

- 系统应采集学习进度、测验成绩、学习时长、LLM 交互次数等数据。
- 画像数据应保存到 `twin_profiles`、`twin_profile_nodes`、`twin_history`。

**FR-302 学生画像展示**

- 学生应能查看整体掌握度、知识节点掌握度、趋势和风险提示。
- 教师应能查看关联学生的画像摘要。

**FR-303 课程画像**

- 系统应支持按 `student_id + course_id` 生成课程级画像。
- 输出应包含课程匹配节点、弱项、趋势、风险和摘要。

**FR-304 弱项识别**

- 系统应基于掌握度识别薄弱知识点。
- 弱项应包含优先级、掌握分和推荐资源。

**FR-305 个性化学习路径**

- 系统应为学生生成个性化路径。
- 路径应包含弱项节点、学习顺序、资源建议和 LLM 解释。
- 当节点掌握度变化时，系统应支持更新路径节点状态。

### 5.5 作业中心

**FR-401 教师发布作业**

- 教师应能创建作业，支持主观题、客观题、选择题、代码题和代码实践。
- 作业应支持标题、说明、班级、截止时间、迟交开关、总分、评分标准、课程节点上下文和题目列表。
- 作业可保存为草稿或立即发布。

**FR-402 作业状态管理**

- 教师应能编辑作业。
- 教师应能发布、关闭、重开作业。
- 学生只应看到可访问的作业。

**FR-403 学生提交作业**

- 学生应能查看作业详情并提交答案。
- 系统应记录提交时间、答案、提交状态和所属学生。

**FR-404 AI 辅助批改**

- 教师应能对提交记录触发 AI 辅助批改。
- AI 批改应返回建议分、反馈和评分依据。
- 教师应能选择重新生成 AI 批改结果。

**FR-405 教师终审**

- 教师应能录入最终得分和评语。
- 终审结果应覆盖 AI 建议作为最终成绩。

**FR-406 AI 辅助出题**

- 教师应能输入主题、题型、数量、难度和额外要求生成题目草稿。
- 生成题目应可继续编辑后发布。

**FR-407 代码实践判题**

- 代码实践题应支持测试用例。
- 系统应通过 go-judge 沙箱进行隔离运行。
- 判题超时、运行错误和测试失败应有明确反馈。

### 5.6 教师看板与教师数字孪生

**FR-501 班级概览**

- 教师应能查看班级整体学习情况。
- 指标应包含学生数量、掌握度、学习风险等摘要信息。

**FR-502 学生详情与趋势**

- 教师应能查看单个学生详情。
- 教师应能查看学生掌握度趋势。

**FR-503 节点排名与热力图**

- 教师应能查看指定知识点的学生排名。
- 教师应能查看知识点热力图，包括平均掌握度和学习人数。

**FR-504 教师数字孪生**

- 系统应基于教师互动、教研、批改和干预等事件生成教师画像。
- 教师应能查看教师画像摘要、维度钻取和 AI 建议。

### 5.7 AI 干预任务包

**FR-601 学生诊断**

- 教师应能选择学生并触发诊断。
- 诊断应基于学生画像、学习进度、测验和作业表现。

**FR-602 干预草稿生成**

- 教师应能生成 AI 干预任务包草稿。
- 草稿应包含策略摘要、推荐概念、推荐视频和练习题。

**FR-603 干预包编辑与推送**

- 教师应能编辑草稿内容。
- 教师应能将干预包推送给学生。

**FR-604 学生处理干预包**

- 学生应能查看收到的干预包。
- 学生应能接受或拒绝任务包。
- 学生应能保存答案和更新完成进度。

**FR-605 教师跟踪与评分**

- 教师应能查看学生干预进度。
- 教师应能对干预包中的题目进行评分与反馈。

### 5.8 教学互动与教研协同

**FR-701 公告管理**

- 教师应能创建、编辑、删除公告。
- 学生应能查看公开公告。
- 公告发布应记录为教师互动事件。

**FR-702 讨论话题**

- 教师应能创建、编辑、删除讨论话题。
- 学生应能查看公开话题并提问。
- 教师应能回复学生问题。
- 互动系统应统计近期学生问题数、教师回复数和平均响应时间。

**FR-703 教研记录**

- 教师应能创建、编辑、删除教研记录。
- 教研记录应支持活动类型、标题、描述、资源链接、班级和课程上下文。
- 教研行为应同步沉淀到教师数字孪生事件。

### 5.9 行业情报

**FR-801 岗位采集**

- 学生应能输入关键词、国家/城市、岗位数量、数据源和相关性阈值发起分析。
- 系统应支持国内与海外并行采集。
- 数据源应支持 LinkedIn、Indeed 等配置项。

**FR-802 相关性过滤**

- 系统应按关键词和岗位内容计算相关性得分。
- 低于阈值的岗位不应进入核心分析结果。

**FR-803 LLM 技能分析**

- 系统应解析岗位描述，提取技能、经验、学历、岗位要求等信息。
- 系统应生成技能排名、岗位分布、经验分布、学历分布和技能热力图。

**FR-804 任务状态**

- 学生应能查看当前任务状态。
- 系统应支持任务结果恢复、重新分析和取消。

### 5.10 管理端

**FR-901 用户查看**

- 管理员应能查看学生列表和教师列表。

**FR-902 LLM 日志查看**

- 管理员应能查看 LLM 调用日志。
- 日志应包含时间、用户、模块、模型和请求响应摘要。

## 6. 数据需求

### 6.1 主数据

- 用户：`users`
- 教师学生关系：`teacher_student_links`
- 会话：`sessions`
- 课程：`courses`
- 课程节点：`course_nodes`
- 学习资源：`resources`
- 测验记录：`quiz_attempts`
- 学习计划：`learning_plans`
- 学生画像：`twin_profiles`、`twin_profile_nodes`、`twin_history`
- LLM 日志：`llm_logs`
- 用户状态：`user_states`

### 6.2 文件与资源数据

- 课程 JSON：`data/course/big_data.json`
- 用户历史课程数据：`data/user_data/*/big_data.json`、`data/user_data/*/graph.json`
- PDF 资源：`data/Book`
- 视频资源：`data/Video/video_urls.json`
- 向量库：`data/chroma_db`
- 发布种子：`release/init_seed.sql`、`release/app_release.db`

### 6.3 数据一致性要求

- 课程、资源、测试应以 SQLite/MySQL 实体表为主。
- 历史 JSON 仅作为迁移兜底或静态资源保留。
- 测验完成后应同步写入测验实体、课程完成状态和数字孪生画像。
- 作业与干预相关记录应保持学生、教师和课程节点上下文可追溯。

## 7. 非功能需求

### 7.1 性能

- 后端应启用 GZip 压缩，减少大响应体传输成本。
- 课程图谱读取应支持缓存，降低重复数据库读取。
- RAG、Agent、向量库等重资源应采用懒加载或启动预热，避免阻塞常规接口。
- 行业情报采集应支持并行抓取，长任务应提供状态查询。

### 7.2 可用性

- 前端页面应按学生、教师、管理员角色隔离导航。
- 后端应对未登录、无权限、资源不存在、参数错误给出明确 HTTP 状态码。
- 外部服务失败时，应尽量返回可理解的失败原因。

### 7.3 安全

- 受保护接口应依赖登录态和角色校验。
- 会话 Cookie 应使用 HttpOnly。
- 作业、干预、互动、教研等教师侧资源应校验创建者或关联教师身份。
- 代码实践运行应通过沙箱隔离，避免直接在主服务执行用户代码。

### 7.4 可维护性

- 后端模块应按业务域拆分：数字孪生、作业、行业情报、教学互动、教研、干预、看板等。
- 前端 API 封装应与页面解耦，类型定义集中维护。
- 数据访问应通过 `DatabaseModule` 统一封装，支持 SQLite/MySQL 切换。
- 重要变更应同步更新 `docs/` 下接口、数据库和模块文档。

### 7.5 可观测性

- 系统应记录后端运行日志。
- LLM 调用应记录到 `llm_logs`。
- 数据源和迁移过程应保留日志或报告。
- 后端应提供自测脚本用于接口冒烟验证。

### 7.6 兼容性

- 后端运行环境：Python 3.10+。
- 前端运行环境：Node.js 18+、npm 9+。
- 默认数据库：SQLite；可通过环境变量切换 MySQL。
- 判题沙箱依赖 Docker。

## 8. 约束与依赖

### 8.1 外部依赖

- LLM 服务：通过 `.env` 配置 `model_name`、`base_url`、`api_key`、`embedding_model`。
- RAG 向量库：依赖本地 `data/chroma_db` 和资源入库流程。
- OJ 判题：依赖 `go-judge-sandbox` Docker 服务。
- 行业岗位采集：依赖 JobSpy 相关抓取能力和外部招聘网站可用性。

### 8.2 技术约束

- 当前课程 ID 默认使用 `course_big_data`。
- 多课程能力已有部分数据结构支撑，但运行逻辑仍以默认课程为主。
- 历史文档和部分源码注释存在编码显示问题，不影响核心功能但影响阅读体验。
- 部分模块仍处于 JSON 与实体表并存的迁移阶段，需要持续收敛。

## 9. 验收标准

### 9.1 后端验收

- 能启动后端服务：

```powershell
python main.py
```

- 能执行接口自测：

```powershell
python scripts\backend_api_selftest.py --base-url http://127.0.0.1:8000
```

- 登录、当前用户、课程图谱、学习节点、测验、数字孪生、教师看板等核心接口可访问。

### 9.2 前端验收

- 能安装依赖并完成构建：

```powershell
cd frontend-vue
npm install
npm run build
```

- 学生、教师、管理员登录后进入对应端。
- 主要页面路由不出现空白页或权限错跳。

### 9.3 业务验收

- 学生能完成“学习资源查看 -> AI 问答 -> 测验 -> 画像更新 -> 路径推荐”的闭环。
- 教师能完成“查看班级 -> 创建作业 -> 学生提交 -> AI 批改 -> 教师终审”的闭环。
