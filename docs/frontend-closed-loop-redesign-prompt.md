# AI-Education 前端闭环工作台改造提示词

你是 AI-Education 项目的资深产品设计师与前端工程师。请基于需求文档的业务主线改造现有 Vue 前端，不要把页面做成模块陈列或宣传型界面，而要做成证据闭环驱动的教学工作台。

## 项目背景

AI-Education 的核心业务闭环是：

课程底座发布 -> 学生学习/测验/作业/互动产生证据 -> 学生画像与诊断 -> 个性化路径 -> 教师看板发现问题 -> 教师审核干预任务 -> 学生执行 -> 结果回流画像、诊断和课程运行评估。

系统必须清楚区分 AI 建议、教师确认、已发布、学生可见、执行完成、证据回流等状态。凡涉及课程底座发布、职业能力映射、干预任务包下发、作业覆盖知识点确认等关键动作，都不能让界面暗示 AI 可以绕过教师或管理员直接生效。

## 设计目标

1. 把前端从“模块入口集合”改成“下一步任务工作台”。
2. 学生端优先回答“我今天应该做什么”。
3. 教师端优先回答“哪些风险需要处理、依据是什么、下一步怎么处置”。
4. 管理端优先回答“权限、AI 调用、运行异常和数据治理是否可控”。
5. 页面文案使用用户视角，减少“画像、孪生、智能体”等系统内部词的裸露。

## 信息架构要求

学生端导航建议：

- 今日学习
- 学习中心
- 个性化路径
- 作业测验
- 学习诊断
- 老师任务
- 互动答疑
- 职业能力
- 设置

教师端导航建议：

- 教师看板
- 课程底座
- 作业测验
- 风险诊断
- 干预任务包
- 教学互动
- 教研协同
- 行业能力
- 教师画像

如果当前路由无法立即合并页面，可以先改显示文案与页面内分区，保持现有路由不变。

## 学生端首页改造要求

学生首页第一屏必须以“今日优先任务”为核心，而不是知识图谱或大屏指标。

第一屏建议包含：

- 一句任务摘要：例如“今天建议先完成 1 个路径节点、1 个待交作业，并补一次测验证据。”
- 主任务卡：继续个性化路径、完成作业、处理老师任务、继续当前知识点。
- 证据状态：诊断依据是否充分、当前是否有证据不足的知识点。
- 当前学习定位：课程/章节/小节/知识点，作为辅助信息。

知识图谱、画像摘要、职业能力、通知等内容可以保留，但不要抢占第一屏主任务。

## 教师端看板改造要求

教师看板默认页必须以“待处理队列”和“风险处置”为核心。

第一屏建议包含：

- 待处理队列：风险学生、低掌握薄弱点、低有效度 5E 记录、待补资源/测验、待下发干预建议。
- 风险学生卡：学生、掌握度、证据等级、薄弱点、建议动作。
- 快捷动作：查看证据、生成任务包、补测验、补资源。
- 状态说明：AI 建议只是草稿，教师确认后才下发。

图表可以保留，但应服务于处置，不要只展示数据。

## 课程底座页面要求

课程数字孪生页应表达流程：

课程结构 -> 资源候选 -> 测验定义 -> 能力映射 -> 教师审核 -> 发布课程底座。

所有状态必须明确：

- 草稿：学生不可见
- 待审核：需要教师确认
- 已确认：进入正式课程底座
- 已发布：学生端、诊断链路和路径推荐可用

运行评估中的资源缺口、测评缺口、能力支撑缺口要转化为可处理任务，而不是只展示分数。

## 文案规则

学生端使用温和、可执行的词：

- 学习诊断
- 建议补充证据
- 老师布置的补学任务
- 职业能力达成
- 继续学习

教师端使用审核和证据词：

- 证据等级
- 诊断依据
- AI 草稿
- 教师确认后下发
- 已回流
- 待补证据

避免把“AI 生成”写成正式结果，除非界面同时标明“待教师确认”。

## 视觉规则

这是教学与证据治理工作台，不是营销页。

- 减少大型 hero 和装饰性阴影。
- 优先使用队列、表格、时间线、状态条和证据卡。
- 状态色固定：蓝色=可执行，绿色=已完成/已确认，橙色=待审核/证据不足，红色=风险/失败，灰色=草稿/不可见。
- 卡片保持清晰紧凑，避免页面卡片套卡片。
- 重要按钮写清楚动作结果，例如“生成任务包草稿”“确认并下发”“查看证据”。

## 实施顺序

1. 调整导航显示文案，让用户先看到任务而不是模块名。
2. 重排学生首页第一屏，突出今日优先任务和证据状态。
3. 重排教师看板第一屏，突出待处理队列和风险处置。
4. 优化课程底座页面流程状态和发布边界说明。
5. 合并或弱合并作业/测验体验。
6. 补管理端治理入口。
7. 最后统一全局视觉变量和状态组件。

## 验收标准

- 学生登录后 5 秒内能判断下一步该做什么。
- 教师登录后 5 秒内能看到最需要处理的风险或待办。
- 所有 AI 输出在正式影响学生端前都有“教师确认”或“管理员确认”的界面边界。
- 诊断、路径、作业、测验、干预任务之间能看到证据回流关系。
- 页面不再依赖大面积 hero 或装饰卡片表达重点。
